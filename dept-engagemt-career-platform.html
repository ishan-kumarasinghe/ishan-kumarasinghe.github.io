Project Overview

The Department Engagement & Career Platform (DECP) is a full-stack, production-grade application designed to connect university students, faculty, and alumni within an academic department. It provides a professional networking experience -similar to LinkedIn- tailored for department-level engagement, featuring a social feed, job board, real-time chat, and intelligent notifications.

Rather than building a monolithic application, DECP was engineered from the ground up as a distributed microservices system — decomposed into independently deployable services that communicate through both synchronous REST APIs and asynchronous event-driven messaging. The entire stack is containerized with Docker and deployed to AWS using ECS Fargate, behind an Application Load Balancer, with managed message brokering through Amazon MQ.

This project demonstrates real-world proficiency in distributed systems design, cloud infrastructure, DevOps practices, and cross-platform development spanning both web (React) and mobile (React Native/Expo).

Microservices Architecture

System Overview

DECP follows a domain-driven decomposition strategy, where each bounded context in the business domain maps to an independent microservice with its own database, codebase, and deployment lifecycle.

Technology Stack
Runtime Node.js 20 (Alpine Linux)
Framework Express.js
Database MongoDB Atlas (separate DB per service)
Message Broker RabbitMQ (AMQP 0-9-1)
Authentication JWT with HTTP-only refresh tokens
API Gateway Express + http-proxy-middleware
Security Helmet, CORS, express-rate-limit, bcrypt
Web Frontend React 18, Vite, Tailwind CSS
Mobile Frontend React Native (Expo)
Containerization Docker, Docker Compose
Cloud Platform AWS (ECS Fargate, ALB, Amazon MQ, SSM, CloudWatch)

Deployment

AWS Service Purpose Configuration
ECS Fargate Serverless container orchestration 6 services, auto-scaling capable
Application Load Balancer Traffic routing & SSL termination Path-based routing: /api/* → API Gateway, /* → Frontend
Amazon MQ Managed RabbitMQ broker mq.t3.micro, single-instance, AMQPS (TLS)
SSM Parameter Store Secrets management JWT secrets, MongoDB URIs, RabbitMQ URL
CloudWatch Centralized logging & monitoring Log groups per ECS service
Cloud Map Service discovery namespace decp.local with DNS-based resolution
IAM Access control Task execution role with SSM + CloudWatch policies
EC2 Security Groups Network-level firewalling ALB SG → Container SG (self-referencing for internal traffic)

Key Features

Student Lifecycle Management

From registration to graduation, the system supports every academic milestone

Role-Based User Access

Admins, students, supervisors, and examiners access distinct interfaces and actions based on their roles

Examiner Assignment

Admins assign examiners while the system prevents duplicates or role conflicts automatically

Submission Portal

Students upload half-yearly and final reports; examiners provide structured evaluations and feedback

Enrollment Module

Students enroll online and admins review and approve submissions of students

Email Notification System

Automated emails for submission reminders, approval status, and examiner feedback using customizable templates
